# Posterior predictive plots (`scripts/plot_ppd.py`)

*2026-08-28.  Companion to `scripts/plot_corner.py`; reviewed and validated
end-to-end against the stored model deterministics (agreement $\sim 10^{-6}$
relative, float32 accumulation level).*

## The idea

The model infers a rate density over source-frame primary mass, mass
ratio, and redshift,

$$
n(m_1, q, z \mid \theta)
  = \frac{\mathrm{d}N}{\mathrm{d}m_1\,\mathrm{d}q\,\mathrm{d}V\,\mathrm{d}t}
  = R \, e^{\log \mathrm{d}N(m_1, q, z)},
$$

where $\log \mathrm{d}N$ is `LogDNDMDQDV` normalized so that
$m_{\rm ref}\, e^{\log \mathrm{d}N(m_{\rm ref},\, q_{\rm ref},\, z_{\rm ref})} = 1$
at the reference point
$(m_{\rm ref}, q_{\rm ref}, z_{\rm ref}) = (30\,M_\odot,\, 1,\, 10^{-3})$,
and $R$ is the sampled rate density there ($\mathrm{Gpc^{-3}\,yr^{-1}}$).
A *posterior predictive distribution* for this object is the family of
curves $\{\, n(\cdot \mid \theta_i) \,\}$ over posterior draws $\theta_i$:
push every draw through the population model and summarize the resulting
curve ensemble pointwise — median and an equal-tailed 90% band at each
grid point.

`plot_ppd.py` shows three one-dimensional views of $n$, in two flavors:

- **Slices** (default): the density along one axis with the other two
  *held at the reference values*, e.g.
  $m_1\, \mathrm{d}N/\mathrm{d}m_1\,\mathrm{d}q\,\mathrm{d}V\,\mathrm{d}t$
  at $q = 1$, $z = z_{\rm ref}$ as a function of $m_1$.  These are
  conditionals, cheap and exact, because the model already tabulates
  them per draw (see below).
- **Marginals** (`--marginal`): the other dimensions are *integrated
  out*,

  $$
  m_1 \frac{\mathrm{d}N}{\mathrm{d}m_1\,\mathrm{d}V\,\mathrm{d}t}
    = m_1 \int \mathrm{d}q \; n(m_1, q, z_{\rm ref}),
  \qquad
  R(z) = \int \mathrm{d}m_1\, \mathrm{d}q \; n(m_1, q, z).
  $$

  These are the physically integrated quantities, but each posterior
  draw requires rebuilding the population model and quadrature.

The two flavors answer different questions and generally differ in both
shape and level (the $q$-marginal weighting differs from the $q = 1$
slice; the mass integral is dominated by the $\sim 10\,M_\odot$ peak
rather than the reference mass).  Neither involves the cosmology
parameters: $n$ is intrinsic (source frame, per comoving volume), so
$h$, $\Omega_M$, $w$ enter only through the posterior correlations
already baked into each draw — most importantly through
$R = N_{\rm obs}/\mu_{\rm sel}$, where the selection integral does
depend on cosmology.  Cosmology *would* need explicit handling only for
observables ($\mathrm{d}N/\mathrm{d}z$, detector-frame masses,
distances).

The true population is overlaid from the pop config.  Pop configs carry
shape parameters but no rate, so the truth curve is **anchored to the
posterior-median $R$**: its shape is exact, its overall level inherits
the fit.  A uniform log-offset between truth and band (seen in the evo7
runs) therefore means the posterior mis-fits the density at/near the
reference point, not a normalization bug.

## Implementation notes

**Slice mode reads, it does not compute.**  `pop_cosmo_model`
(`intensity_models_fast.py:1326-1332`) records per draw, on the fixed
grids in `intensity_models_fast.coords` ($m$: 128 log-spaced in
$[1, 450]$; $q$: 128 in $(0, 1]$; $z$: 128 $\log(1{+}z)$-spaced in
$[0, 20]$):

| netCDF variable | quantity |
|---|---|
| `mdNdmdVdt_fixed_qz` | $m\, R\, e^{\log \mathrm{d}N(m,\, q_{\rm ref},\, z_{\rm ref})}$ on the $m$ grid |
| `dNdqdVdt_fixed_mz`  | $m_{\rm ref}\, R\, e^{\log \mathrm{d}N(m_{\rm ref},\, q,\, z_{\rm ref})}$ on the $q$ grid |
| `dNdVdt_fixed_mq`    | $m_{\rm ref}\, R\, e^{\log \mathrm{d}N(m_{\rm ref},\, q_{\rm ref},\, z)}$ on the $z$ grid |

so slice mode is pure netCDF post-processing over *all* draws.  Older
`.nc` files without these variables exit with a pointer to `--marginal`.

**Marginal mode maps over thinned draws.**  `--ndraw` (default 500)
draws are thinned at random; for each, `build_population_model` is
rebuilt inside a jitted function and `jax.lax.map` runs them sequentially
(vmapping would multiply the internal PISN grids by the number of draws
in memory).  Per draw it evaluates one $(n_m, n_q)$ plane at
$z_{\rm ref}$ for the $m_1$/$q$ marginals and one $(n_z, n_m, n_q)$ cube
for $R(z)$, integrating with `jnp.trapezoid` on the same $m$/$q$ grids
as the slices.  About 25 s for 500 draws on CPU.  This is plotting-only
post-processing — the likelihood/selection consistency rule for
approximations does not bind here.

**The truth goes through the identical code path.**  Slice-mode truths
replicate the deterministics' formula with `ld_true.mref/.qref/.zref`;
marginal-mode truths call the same `_one` function as the posterior
draws with $R = \operatorname{median}(R)$.  No separately maintained
truth formula exists to drift.

**Run settings are auto-detected, not assumed.**
- `use_low_bump`: inferred from the posterior (`flow` is only recorded
  when the bump is on) for draws, and from `flow > 0` in the pop config
  for the truth.
- `smooth_tail_edge`: read from the `.ini` that `run_inf.py` copies into
  the run dir (same `getboolean` fallback = True); `--hard_tail_edge`
  forces False.  Mismatching this only distorts the *truth* curve near
  $m_{\rm BH}^{\max}$ — the posterior curves are baked into the netCDF.
- Parameters `build_population_model` needs but the posterior/config
  lacks fall back to the model defaults (`PARAM_DEFAULTS`, including
  `mco_min = 4`, `mco_floor = 6`) with a printed note.

**Grid-edge subtleties.**
- `LogDNDV` is hard-zero at $z \ge z_{\max}$.  When `--zmax_plot`
  coincides with the population's $z_{\max}$ (mocks: 6.5) the last
  marginal $z$-grid point would evaluate to exactly zero and drag the
  log-scale panel down, so it is nudged inside *relatively*
  (`zg[-1] *= 1 - 1e-6`); an absolute nudge dies in float32 above
  $z \sim 17$ (half a ULP exceeds $10^{-6}$ there).
- The marginal $z$ grid starts at $z_{\rm ref} = 10^{-3}$, not 0,
  matching the model's reference convention.
- Log-scale y-limits are set from the band maximum
  ($[10^{-7} y_{\max},\, 3 y_{\max}]$) so the hard-zero regions (below
  $m_{\rm BH}^{\min}$, above $z_{\max}$) don't stretch the axes.

**Parameter stacking.**  All posterior variables are flattened with the
same `reshape(-1)` over `(chain, draw)`, so thinning indices stay
aligned across parameters.  Everything stays float32 (the posterior's
dtype); the validation showed agreement with the stored deterministics
at the float32 summation level, so x64 is unnecessary for plotting.

## Usage

```bash
cd scripts
uv run python plot_ppd.py --run endO5_fullcosmo_evo7_x2sel \
    --pop_config pop_configs/mock_O5_width15.txt
uv run python plot_ppd.py --run ... --marginal --ndraw 500
```

Outputs `<nc>_ppd.png` / `<nc>_ppd_marginal.png` next to the netCDF.
Flags: `--level` (band mass, default 0.90), `--zmax_plot` (default 6.5),
`--hard_tail_edge`, `--seed` (thinning), `--nc`, `--out`, `--runs_dir`.
